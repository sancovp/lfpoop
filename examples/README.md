# examples/ — lfpoop on code it has never seen

**`wordstats.py`** is a tiny, plain-Python text-analytics program. It imports
nothing from lfpoop. It is the "other code" the library reads and transforms —
the whole point is that lfpoop takes code it has never seen and emits its
onion, proven by the subject's *own* test suite.

Run it:

```bash
python3 examples/onionize_wordstats.py
```

That drives the full pipeline over `wordstats.py`:

1. **onionize** → writes **`wordstats_onion.py`** (checked in, so the
   transformed code is readable here on GitHub): every function becomes BASE
   block functions + a META chain under its original name; the `Report` class
   opens at method grain; the lambda sort-key seals as one opaque block; the
   learned roll-up and the module onion (`WordstatsOnion`, carrying its
   function rings and class rings as data) are appended.
2. **shadow** → runs `test_wordstats.py` (the subject's own 6-check suite)
   against the onionized build in a subprocess. **Green = the transform
   preserved behavior.** The example is only valid if this passes.
3. **class-ify** → turns the curried `word_count(text, stopwords)` into a
   class: `stopwords` binds at construction, `text` stays the call surface.
4. **predict** → treats the functions as a pool and derives the composition
   chain for a `summary`-shaped result by deduction.

| file | what it is |
|---|---|
| `wordstats.py` | the subject — plain Python, lfpoop-free |
| `test_wordstats.py` | the subject's own acceptance suite (the shadow gate) |
| `onionize_wordstats.py` | the runner — drives the whole pipeline, prints what lfpoop learned/emitted/predicted |
| `wordstats_onion.py` | **the generated onion** (regenerated by the runner) |
